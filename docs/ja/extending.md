# ヘルプの追加

<a id="directory-layout"></a>

## ディレクトリ構成

ガイド、プラグインのヘルプ、運用者のディレクトリは、同じ構成です。

```text
index.yml          # サイドバーの章
map.yml            # 画面とトピックの対応 (mapping.md)
en/                # 言語ごとのディレクトリ
  <topic>.md       # トピック。最初の # の見出しがタイトル
  _support.md      # (運用者だけ) すべてのページに出す囲み
  _support/<topic>.md  # (運用者だけ) 1 つのトピックに出す囲み
  _insertions/<name>.md  # (プラグインだけ) ガイドのトピックに挿入するセクション
ja/
  <topic>.md
images/            # トピックが相対のリンクで表示する画像
```

`index.yml` には、章とそのトピックを並べます。トピックは ID だけか、ID とサイドバーの表示名です。表示名は、トピックがユーザーの言語に翻訳されていないあいだ使います (翻訳されたトピックは、その見出しを表示します)。

```yaml
sections:
  - id: support
    title: { en: Support, ja: サポート }
    topics:
      - support/contact
      - { id: support/hours, title: { en: Opening hours, ja: 受付時間 } }
```

ユーザーの言語にないトピックは、英語で、その旨を添えて表示します。

プラグインは、これらのファイルを最初に必要になったときに一度だけ読み込み、メモリーに保持します。変更したあとは Redmine を再起動してください (開発環境では、変更したファイルを読み込み直します)。`index.yml` や `map.yml` が YAML として正しくないとき、またはマッピングでないときは、そのファイルを使わず、ファイル名を Redmine のログに警告として出力します。ほかのファイルとディレクトリは引き続き使えます。

<a id="plugins"></a>

## プラグイン

Redmine のプラグインは、ルートに上の構成の `help/` のディレクトリを置くだけで、ヘルプを追加できます。Redmine Kit Help は、インストールされたすべてのプラグインからこれを見つけます。登録は要りません。プラグインの章は、サイドバーでガイドの章のあとに出ます。プラグインの `map.yml` で、プラグインの画面 (プラグインのコントローラー) をトピックに対応付けます。トピックは、ガイドのものと重ならないよう、プラグインの名前のディレクトリの下に置きます (たとえば `aws-ses/sending`)。

<a id="screens-of-the-new-ui"></a>

### 新しい UI の画面

Redmine Kit UI の新しい UI でのプラグインの画面 (マニフェストの `screens`) には、追加の設定は要りません。新しい UI はプラグインの画面を `<plugin>:<component>` と呼び、Redmine Kit Help はマニフェストにあるその画面のパスから Redmine のルートを求めます。そのため画面は、Redmine の UI と同じく、ルートのコントローラーとアクションに `map.yml` が対応付けたトピックを開きます。複数の画面が描くコンポーネント (新規作成と編集のフォーム) は、マニフェストで最初の画面で探します。コントローラー (`checklist_items`) を対応付けると、そのアクションすべてに 1 つのトピックを対応付けられます。プラグインがプロジェクトの設定に追加するタブは、どちらの UI でも `projects#settings?tab=<tab>` です ([mapping.md](mapping.md#the-new-ui))。

<a id="sections-in-the-guides-topics"></a>

### ガイドのトピックへのセクションの挿入

Redmine の画面 (チケット、プロジェクトの設定、管理) を変えるプラグインは、その画面を説明するガイドのトピックにセクションを追加できます。読者は、画面の説明と同じ場所でプラグインの説明を読めます。セクションは、`<言語>/_insertions/` に置く Markdown のファイルで、1 つが 1 つのセクションです。英語のファイルの先頭のフロントマターに、ガイドのトピックと、そのセクションのあとに挿入する見出しの英語のアンカー ([mapping.md](mapping.md#anchors)) を書きます。

```markdown
---
topic: user/issues
after: Listing-of-the-issue
---
## Checklist

The issue's page shows the project's checklist after the description …
```

- **挿入する位置:** `after` の見出しのセクションの終わり、つまり、同じかより上のレベルの次の見出しの前 (その見出しの下位の見出しのあと) です。セクションは、その見出しと同じレベルの見出しで始めます。
- **トピックの一部になる:** 挿入したセクションの見出しは、トピックの目次とアンカーに入ります。検索はその本文も対象にし、画面の `map.yml` でトピックをそのセクションの位置で開けます (`checklist_items#index: user/issues#Checklist`)。リンクと画像は、トピックに書いたときと同じく、トピックのディレクトリからの相対パスです (`../checklist/checklist.md`)。Markdown は、トピックと同じフォーマッターとサニタイザーで表示します。
- **ラベル:** 挿入したセクションの見出しには、プラグインの名前 (`Redmine::Plugin#name`) のラベルが付きます。どちらの UI でも、ヘルプのページとサイドパネルに表示します。
- **同じ見出しに複数のプラグイン:** 「管理」›「プラグイン」の順 (プラグインの ID の順)、次にファイル名の順に並べます。
- **言語:** 翻訳は、言語のディレクトリにある同じ名前のファイルです (`ja/_insertions/<name>.md`)。フロントマターは書きません (位置は英語のファイルのものを使います)。見出しは英語のファイルと一対一に揃えます。プラグインに翻訳がない言語のトピックには英語のセクションを表示し、ラベルにその旨を添えます (「Redmine Kit Checklist (English)」)。
- **トピックや見出しがないとき:** そのセクションは挿入せず、`map.yml` が YAML として正しくないときと同じく、ファイル名を Redmine のログに警告として出力します。プラグインのほかのヘルプは引き続き使えます。プラグインをリリースする前に、下のチェックを実行してください。
- **運用者による置き換え:** 運用者のディレクトリが置き換えたトピックには、プラグインのセクションを挿入しません。運用者の文章をそのまま表示します。プラグインの説明が必要なら、運用者の文章に書けます。

<a id="checking-a-plugins-help"></a>

### プラグインのヘルプのチェック

rake タスクで、インストールされたガイドに対してプラグインの `help/` をチェックします。`map.yml` と `index.yml` のトピックとアンカーがあること、翻訳に英語のトピックまたはセクションがあり見出しの数が同じであること、セクションのトピックと見出しがあり、その見出しと同じレベルの見出しで始まり、トピックの見出しと重ならないことを確認します。問題ごとにファイル名を出力し、問題があれば終了ステータス 1 で終わります。

Redmine のディレクトリで、すべてのプラグインか、1 つのプラグインについて実行します。

```sh
bin/rails redmine_kit:help:check RAILS_ENV=production
bin/rails redmine_kit:help:check PLUGIN=redmine_kit_checklist RAILS_ENV=production
```

Redmine Kit Help とガイドがインストールされた環境では、プラグインのテストで同じことを確認できます。

```ruby
assert_empty RedmineKit::Help::Check.new.problems(:redmine_kit_checklist)
```

<a id="the-operators-directory"></a>

## 運用者のディレクトリ

`REDMINE_KIT_HELP_EXTRA_PATH` で、Redmine の外に置いた同じ構成のディレクトリを指定します (たとえば派生のイメージや、マウントしたボリューム)。次のことができます。

- **ページを追加する:** 社内の問い合わせ先、ホスティングのサービスのサポートなど、独自のトピックと章を追加します。これらの章は、サイドバーの先頭に出ます。
- **ページに囲みを追加する:** `<言語>/_support.md` をすべてのページの下に、`<言語>/_support/<topic>.md` を 1 つのトピックの下に出します (ヘルプデスクの番号、社内でのチケットの使い方など)。ユーザーの言語の囲みがないときは、英語の囲みを出します。
- **トピックを置き換える:** ガイドやプラグインと同じパスのトピックは、それを置き換えます。
- **画面を対応付ける:** 運用者の `map.yml` は、プラグインとガイドより先に探します。

<a id="precedence"></a>

## 優先順位

| 対象 | 順 (先が優先) |
| --- | --- |
| トピック | 運用者のディレクトリ、プラグイン、ガイド |
| 対応表の画面 | 運用者のディレクトリ、プラグイン、ガイド |
| サイドバーの章 | 運用者のディレクトリ、ガイド、プラグイン (1 つのトピックは 1 回だけ並べる) |
| 囲み | すべてのページの囲み、次にトピックの囲み |
| トピックの同じ位置に挿入するプラグインのセクション | 「管理」›「プラグイン」の順 (プラグインの ID の順)、次にファイル名の順。運用者が置き換えたトピックには挿入しない |
